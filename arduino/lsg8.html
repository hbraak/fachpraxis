Lösung AB 8: Wir bauen uns ein CASSY

Ein eigenes Messgerät für die Entladekurve eines Kondensators

📄 Arbeitsblatt (PDF) 💾 Sketch (.ino) ← AB 6 (Abkühlkurve) AB 4 (ADC) ← Übersicht
Die Leitidee: In Physik liefert das CASSY die Kurve, das Thema ist der Kondensator. Hier ist es umgekehrt — der Kondensator ist nur der Prüfling, das Messgerät ist das Thema. Hauptmessung: C = 100 nF, R = 47 kΩ. Alle Zahlen unten sind Richtwerte; die Schülerwerte dürfen abweichen.

Der Sketch Zeile für Zeile

Ihr tippt den Sketch diesmal nicht ab — dafür solltet ihr ihn lesen können. Hier steht, was jede Zeile tut und warum sie so und nicht anders dasteht. Fast jede Entscheidung im Code ist eine Messgeräte-Entscheidung.

1. Der Schalter BALKEN — ein Gerät, zwei Betriebsarten

const bool BALKEN = true; // true = sehen, false = messen

Dasselbe Programm kann die Kurve zeigen (grobe Balken, langsamer Takt, Laden und Entladen) oder sie messen (100 Zahlen, feiner Takt, nur Entladen). Eine Zeile ändern, neu hochladen — fertig. Genau das ist bei einem echten Messgerät der Unterschied zwischen der Anzeige am Bildschirm und dem Datenexport: Beide stammen aus derselben Messung, aber sie haben verschiedene Aufgaben. Die Anzeige soll man verstehen, die Datei soll man auswerten.

2. Die Konstanten — alles, was ihr anfassen müsst

const int PIN_RC = 2; // laedt und entlaedt const int PIN_MESS = A0; // misst die Kondensatorspannung const int N_SEHEN = 20; // Balkenmodus: wenige Punkte ... const unsigned long DT_SEHEN = 2000; // ... im groben Takt (2 ms) const int N_MESSEN = 100; // Messmodus: viele Punkte ... const unsigned long DT_MESSEN = 200; // ... im feinen Takt (200 us) const unsigned long LADEZEIT = 500; // Ladedauer in ms const unsigned long PAUSE = 3000; // Wartezeit bis zur naechsten Messung

Das ist die komplette „Bedienoberfläche“ des Geräts. DT_MESSEN und LADEZEIT sind genau die Werte, die ihr in Aufgabe 3 und Aufgabe 5 nachgerechnet habt — der Sketch nimmt euch die Physik nicht ab, er führt sie nur aus. Für den Zusatz mit 470 kΩ ändert ihr eine Zahl.

const heißt: Der Compiler darf den Wert fest in den Code einbauen, statt RAM dafür zu reservieren. unsigned long ist nötig, weil Zeiten in µs schnell große Zahlen werden (siehe unten beim Cast) — ein int kann auf dem Uno nur bis 32767 zählen.

3. Der Messwertspeicher

int werte[N_MESSEN]; // der Messwertspeicher (fuer den groesseren Fall)

Das Array wird für den größeren der beiden Fälle angelegt, also 100 Zahlen zu je 2 Byte = 200 Byte von 2048 Byte SRAM (9,8 %). Hier liegt die eigentliche Grenze des Geräts: Mehr Messpunkte kosten RAM, nicht Rechenzeit. Mit N_MESSEN = 900 wäre der Uno voll und würde abstürzen — ohne Fehlermeldung, er läuft einfach wirr weiter. Genau deshalb hat auch ein echtes CASSY eine maximale Messpunktzahl.

4. setup() — einmalig

void setup() { Serial.begin(115200); pinMode(PIN_RC, OUTPUT); digitalWrite(PIN_RC, LOW); anzahl = BALKEN ? N_SEHEN : N_MESSEN; // Betriebsart einstellen dt = BALKEN ? DT_SEHEN : DT_MESSEN; delay(500); // Kondensator sicher leer }

115200 statt der gewohnten 9600 Baud — 12-mal schneller. Das ist keine Kosmetik, siehe Aufgabe 10. A0 braucht kein pinMode, Analogeingänge sind immer Eingänge. Die beiden Fragezeichen-Zeilen übersetzen den Schalter in die zwei Zahlen, mit denen das Programm danach überall arbeitet: anzahl und dt. So steht die Messschleife nur einmal im Code — zwei Kopien würden irgendwann auseinanderlaufen.

5. Laden — der Pin ist die Spannungsquelle

digitalWrite(PIN_RC, HIGH);
Der Trick des ganzen Aufbaus: D2 ist nicht nur ein Schalter, sondern die Spannungsquelle. Bei HIGH liegen 5 V am Pin, der Kondensator lädt über R. Der Strom ist 5 V / 47 kΩ = 0,11 mA — ein Ausgangspin darf 40 mA, also völlig unkritisch. Deshalb braucht die Schaltung kein Netzteil und keinen zweiten Widerstand. Im Balkenmodus wird direkt nach dem HIGH aufgezeichnet — so sieht man die Ladekurve. Im Messmodus wird erst LADEZEIT lang geladen und dann die Entladekurve aufgenommen.

6. Entladen — und warum LOW nicht „aus“ heißt

digitalWrite(PIN_RC, LOW);

LOW bedeutet nicht „Pin abgeschaltet“, sondern „Pin aktiv auf 0 V“. Der Ausgang wird zum GND-Anschluss, und der Kondensator entlädt sich über denselben Widerstand. Deshalb ist τ beim Laden und Entladen identisch — ein Bauteil, zwei Funktionen. Im Balkenmodus sieht man das direkt: Beide Kurven sind gleich schnell, nur spiegelbildlich.

Wollte man den Kondensator stattdessen sich selbst überlassen, müsste man den Pin mit pinMode(PIN_RC, INPUT) hochohmig schalten. Dann würde der Kondensator nur noch über den Eingangswiderstand des Wandlers entladen — τ wäre Minuten statt Millisekunden. Probiert es ruhig aus, es ist eine schöne Demonstration zu Aufgabe 12.

7. aufnehmen() — die wichtigsten vier Zeilen

void aufnehmen() { unsigned long t0 = micros(); // t = 0 ist uns exakt bekannt for (int i = 0; i < anzahl; i++) { while (micros() - t0 < (unsigned long)i * dt) { ; } // auf den Takt warten werte[i] = analogRead(PIN_MESS); // nur messen, NICHT senden } dauer = micros() - t0; // Selbsttest: Ist-Dauer merken }

Warum nicht einfach delay(dt)? Weil sich Fehler dann aufaddieren: Jeder Durchlauf bräuchte dt plus die Zeit für analogRead() plus den Schleifenaufwand. Nach 100 Punkten wäre die Zeitachse um über 11 ms zu lang — und zwar ungleichmäßig. Hier wird stattdessen jeder Messpunkt gegen den festen Startzeitpunkt t0 terminiert: Messpunkt i gehört zur Zeit i · dt, basta. Verzögerungen können sich nicht summieren.

Der Cast (unsigned long) ist kein Schönheitsfehler. Ohne ihn würde i * dt als int gerechnet — und int endet auf dem Uno bei 32767. Schon im Balkenmodus (dt = 2000) wäre bei i = 17 Schluss, danach kämen negative Zeiten heraus und die Schleife würde gar nicht mehr warten. Die Messung sähe aus wie ein senkrechter Absturz. Solche Überläufe sind der häufigste schwer findbare Fehler in Mikrocontroller-Programmen, weil nichts abstürzt — es kommen nur falsche Zahlen heraus.

Gespeichert wird der Rohwert 0…1023, nicht die Spannung. Eine Umrechnung in Volt bräuchte Fließkommarechnung, und die kostet auf dem Uno Hunderte von Mikrosekunden — mitten im Messtakt. Rechnen wird nach hinten verschoben, gemessen wird sofort. Das ist ein Grundprinzip jedes Messgeräts (und nach Aufgabe 12a für das Ergebnis sowieso egal).

Die letzte Zeile ist der eingebaute Selbsttest: Das Gerät misst, wie lange es selbst gebraucht hat. Weicht die Ist- stark von der Soll-Dauer ab, kommt der Prozessor dem Takt nicht nach — dann ist die Zeitachse gestreckt und alle τ-Werte sind falsch (Aufgabe 9).

8. balken_ausgeben() — die Anzeige

for (int i = 0; i < anzahl; i++) { int adc = werte[i]; // Zahl rechtsbuendig, dann " |", dann adc/20 Balken Serial.print(adc); Serial.print(F(" |")); for (int k = 0; k < adc / 20; k++) Serial.print('#'); Serial.println(); }

Ein Zeichen steht für 20 Wandlerstufen, der volle Balken ist also 1023/20 = 51 Zeichen lang. Das ist absichtlich grob: Eine Anzeige muss man auf einen Blick erfassen können. Dass die Zahl zusätzlich dasteht, ist der Übergang zu Teil 2 — man sieht die Kurve und hat gleichzeitig die Zahlen vor sich, mit denen später gerechnet wird.

9. csv_ausgeben() — der Datenexport

Serial.print(F("# Punkte: ")); Serial.print(anzahl); … Serial.println(F("t_us;adc")); for (int i = 0; i < anzahl; i++) { Serial.print((unsigned long)i * dt); Serial.print(';'); Serial.println(werte[i]); }
  • F("...") legt den Text ins Flash statt ins RAM. Ohne das würden die Überschriften rund 100 Byte des knappen Speichers belegen — neben dem 200-Byte-Array spürbar.
  • Semikolon als Trennzeichen, weil das deutsche Excel/LibreOffice das Komma für Dezimalstellen braucht. Die Zeitspalte wird hier berechnet (i · dt) und nicht gemessen — sie ist per Konstruktion exakt gleichmäßig.
  • Die Kopfzeile beginnt mit #, damit man sie beim Import leicht erkennt und überspringt. Sie enthält auch Soll- und Ist-Dauer des Selbsttests — die Messung dokumentiert sich selbst.

10. Und dann von vorn

delay(PAUSE); // Pause, dann misst das Geraet erneut

loop() läuft endlos, das Gerät misst also alle drei Sekunden eine neue Kurve. Praktisch: Ihr könnt am Aufbau wackeln, den Widerstand tauschen oder den Kondensator entfernen und seht sofort, was passiert — ohne neu hochzuladen. Für die Auswertung nehmt ihr einfach einen vollständigen Block zwischen zwei Kopfzeilen.

Teil 1 — Hinsehen: das Gerät in Betrieb nehmen

Aufgabe 1 — Aufbauen und starten

Der Widerstands-Istwert liegt typisch 0,5 % neben dem Aufdruck, z. B. R = 46,6 kΩ (am Lehreraufbau nachgemessen). Mit diesem Wert wird später gerechnet, nicht mit dem Aufdruck.

Was man auf dem Monitor sieht: Zwei Blöcke, die sich endlos abwechseln. Im ersten werden die Balken von Zeile zu Zeile länger, im zweiten kürzer. Beide Male ändert sich am Anfang viel und am Ende fast nichts mehr — die Zeilenabstände sind ja immer gleich, die Sprünge werden aber kleiner.

Woran man Laden und Entladen ohne die Überschrift erkennt:
  • Laden beginnt bei 0 und wächst auf den Maximalwert zu — die Kurve nähert sich von unten einer Grenze und wird dabei immer flacher.
  • Entladen beginnt beim Maximalwert und fällt auf 0 — der größte Sprung steht gleich am Anfang.
  • Entscheidend ist also die Richtung des ersten Sprungs, nicht der Endwert: Beide Verläufe enden „langweilig“.
Die Handskizze soll genau das zeigen: eine Sättigungskurve nach oben und eine Zerfallskurve nach unten, beide mit derselben Krümmung — es ist ja derselbe Widerstand und derselbe Kondensator (siehe Sketch, Abschnitt 6).
Häufige Beobachtung, die kein Fehler ist: Die erste Zeile der Entladephase zeigt oft 1018 oder 1019, die letzte Zeile der Ladephase nur 1017. Dazwischen liegt kein Vorgang, sondern nur das Rauschen der letzten Stufe — der Wandler löst 4,9 mV auf, und so genau ist nichts an diesem Aufbau. Wer hier eine Erklärung sucht, sucht zu genau.

Aufgabe 2 — Was bedeutet die Zahl?

kleinster Wert: 0 groesster Wert: 1023 (10 Bit = 2^10 = 1024 Stufen) eine Stufe = 1/1023 von U_0 = 4,985 V / 1023 = 4,87 mV

Der Widerspruch: Die Formel u(t) = U₀·(1 − e^(−t/τ)) wird tatsächlich niemals fertig — mathematisch bleibt immer ein Rest. Das Messgerät kann diesen Rest aber nur erkennen, solange er größer als eine Stufe ist. Darunter liefert der Wandler zwangsläufig immer dieselbe Zahl.

Das Kriterium kommt vom Wandler, nicht vom Gefühl:
e^(−n) < 1/1023 ⇒ n > ln 1023 = 6,93 ⇒ 7τ

Ab 7τ kann dieser Arduino „voll“ und „fast voll“ gar nicht mehr unterscheiden — länger laden ist für ihn sinnlos. Die Antwort auf die Schlussfrage lautet deshalb: Nicht die Physik legt fest, wann „voll“ ist, sondern das Messgerät. Ein Gerät mit 16 Bit käme auf ln 65535 = 11τ, ein Zeigerinstrument mit 1 % Ablesegenauigkeit schon auf 4,6τ. „Voll“ ist keine Eigenschaft des Kondensators, sondern eine Aussage über den Beobachter.

Dieselbe Zahl 6,93 kommt in Aufgabe 11b noch einmal vor — dort als Grenze, ab der das Gerät beim Entladen nur noch Nullen liefert. Das ist kein Zufall: Der Dynamikbereich eines 10-Bit-Wandlers ist 1024:1, und in einem Exponentialvorgang sind das rund sieben Zeitkonstanten. Mehr Fenster hat das Gerät nicht.

Aufgabe 3 — Wie schnell läuft das ab?

gezaehlt: etwa 15 bis 16 Zeilen, bis sich nichts mehr aendert Dauer: 15 · 2 ms = 30 ms (der Balkenmodus nimmt 20 Punkte ueber 38 ms auf) tau = R · C = 46,6 kOhm · 100 nF = 4,66 ms 30 ms / 4,66 ms = 6,4 tau
Die Probe geht auf: Nach Aufgabe 2 ist bei 6,9τ eine Stufe erreicht — und genau dort, nach etwa 6,4τ, hört die Anzeige auf, sich zu ändern. Die gezählten Zeilen und die gerechnete Zeitkonstante sagen dasselbe. Das ist der erste Moment, in dem das selbstgebaute Gerät und die Theorie sich bestätigen, und er kostet nur eine Multiplikation.
Ladezeit-Probe: 500 ms / 4,66 ms = 107 tau >> 7 tau → reicht bequem

Die Ladezeit ist bewusst großzügig gewählt: Nötig sind hier 7τ = 33 ms, die 500 ms sind also das Fünfzehnfache davon — und reichen damit auch für den Zusatz mit 470 kΩ (τ = 47 ms, 500 ms = 10,6τ) noch bequem aus. An dieser Zahl muss man nichts drehen.

Aufgabe 4 — Warum reicht hier keine Stoppuhr?

Physik-Praktikum: τ = 47 kΩ · 100 µF = 4,7 s t½ = 3,26 s Dieses Blatt: τ = 47 kΩ · 100 nF = 4,7 ms t½ = 3,26 ms Faktor 1000 schneller
Fallt½Stoppuhr-Reaktion 0,2 sUrteil
100 µF (Physik)3,26 s≈ 6 % Fehlerper Hand gut messbar
100 nF (hier)3,26 ms≈ 6000 % Fehlerper Hand unmöglich
Das ist die Begründung für das ganze Blatt. Im Physik-Praktikum ist τ = 4,7 s absichtlich so gewählt, dass die Stoppuhr mitkommt. Hier ist die Kurve 1000-mal schneller: Die ganze Entladung ist vorbei, bevor ein Mensch den Daumen bewegt hat. Unser Gerät erschließt einen Bereich, der der Handmessung prinzipiell verschlossen ist — nicht nur „genauer“, sondern überhaupt erst möglich.

Teil 2 — Messen: von Balken zu Zahlen

Aufgabe 5 — Das Gerät umschalten

# Punkte: 100 Takt: 200 us Messdauer soll: 19800 us ist: 19912 us Messdauer = (100 − 1) · 200 µs = 19800 µs = 19,8 ms = 4,2 tau

Im Balkenmodus waren es 38 ms über 20 Punkte, jetzt 19,8 ms über 100 Punkte. Die Messung ist also kürzer und trotzdem viel feiner.

Warum ein zehnmal feinerer Takt? Für eine Ausgleichsgerade braucht man viele Punkte im brauchbaren Bereich der Kurve, und brauchbar ist nur der Anfang: Dort ist die Kurve steil und die Werte sind groß (siehe Aufgabe 7). Im Balkenmodus lägen auf den ersten 2τ gerade fünf Punkte — damit kann man keine Steigung bestimmen. Mit 200 µs liegen dort 47 Punkte. Umgekehrt wäre der feine Takt für die Anzeige unbrauchbar: 100 Zeilen rauschen in einer Fünftelsekunde durch, da sieht man nichts.
Dass die Messung dafür nur noch 4,2τ statt 6,4τ abdeckt, ist kein Verlust — der Rest der Kurve liegt ohnehin unter der Auflösungsgrenze (Aufgabe 11b).

Aufgabe 6 — Kurve und Schnellschätzung

u = adc / 1023 · 4,985 V (4,87 mV pro Stufe)

Die Kurve fällt von 1017 auf 14 Stufen. Halbwertszeit abgelesen: t½ = 3,24 ms — die Vorhersage aus Aufgabe 3 lautete 3,26 ms. Die Rechnung vor der Messung bestätigt sich auf unter 1 %, damit ist der Aufbau abgesichert.

Referenzmessung am Lehreraufbau (09.10.2026), 100 Punkte, DT = 200 µs: Startwert 1017, Endwert 14 (vorhergesagt: 15), Selbsttest soll 19800 µs / ist 19912 µs — 0,6 % Überhang, das ist der Overhead der letzten Wandlung. Auswertung siehe unten: τ = 4,670 ms, C = 100,2 nF. Abweichungen von diesen Zahlen sind normal: Der Endwert hängt exponentiell von τ ab, aus 10 % Bauteiltoleranz wird dort schnell ein Faktor 2. Ein Endwert zwischen 8 und 25 ist unauffällig — nicht „passend“ rechnen, das ist das Messergebnis.

Teil 3 — Auswerten: wie groß ist C wirklich?

Aufgabe 7 — Linearisierung

u(t) = U₀ · e^(−t/τ) | logarithmieren ln u = ln U₀ − t/τ → Gerade mit m = −1/τ

Hilfsspalte ln u, eingetragen in ein normales lineares Achsenkreuz (kein logarithmisches Papier — sonst wird zweimal logarithmiert).

Welche Punkte darf man nehmen? Nur die mit genügend großem adc-Wert. Eine Quantisierungsstufe ist immer dieselbe absolute Unsicherheit (±0,5 LSB), aber ihr Anteil am Messwert wächst beim Fallen der Kurve dramatisch: bei adc 1000 sind es ±0,05 %, bei adc 100 schon ±0,5 %, bei adc 7 ganze ±7 %. Im ln-Diagramm wird daraus ein Fehlerbalken von ±0,07 — die letzten Punkte streuen also am stärksten und würden die Gerade am kräftigsten verdrehen. Dazu ist ln 0 gar nicht definiert.
Praxisregel: nur Punkte mit adc ≥ 100 verwenden — das sind die ersten 55 Punkte bis t = 10,8 ms. Das deckt 90 % des Spannungsabfalls ab und lässt immer noch 55 Punkte für die Ausgleichsgerade übrig — mehr als genug. Man sieht die Grenze den Rohdaten direkt an: am Ende steht mehrfach derselbe Wert, dann springt es um ganze Stufen, und bei t = 18,8 ms geht der Wert sogar wieder hoch (17 nach 18). Das ist kein Tricksen, sondern die Auflösungsgrenze des eigenen Geräts — man muss sie nur benennen.
Was es wirklich ausmacht — dieselbe Messreihe, drei Entscheidungen (C mit dem gemessenen R = 46,6 kΩ):
verwendete PunktenτCR²
adc ≥ 100 (Empfehlung)554,670 ± 0,002 ms100,2 nF0,99999
alle 100 Punkte1004,622 ± 0,007 ms99,2 nF0,99977
nur die letzten (adc < 20)85,0 ± 0,7 ms108 nF0,886
Aus dem Schwanz allein kommt eine Unsicherheit von 14 %, aus dem guten Bereich 0,04 % — Faktor 350, ohne eine einzige zusätzliche Messung. Bemerkenswert ist auch die mittlere Zeile: Alle Punkte mitzunehmen kostet nur 1 % Genauigkeit. Ein ungewichteter Fit ist also nicht falsch, nur unnötig schlechter — der Unterschied ist eine Frage der Sorgfalt, nicht des Bestehens.
Steigungsdreieck: m ≈ −214 1/s τ = −1/m = 1/214 1/s = 4,67 ms

Aufgabe 8 — Kapazität

C = τ / R = 4,670 ms / 46,6 kΩ = 100,2 nF Abweichung vom Aufdruck: (100,2 − 100)/100 = +0,2 %

Folienkondensatoren haben typisch ±5 % (teils ±10 %) Toleranz. Der gemessene Wert liegt also klar innerhalb der Toleranz — und zwar deutlich besser als nötig.

Teil 4 — Wie gut ist unser Messgerät?

Aufgabe 9 — Der Selbsttest des Geräts

# Punkte: 100 Takt: 200 us Messdauer soll: 19800 us ist: 19912 us
BeitragBetragUrsache
letzte Wandlung+112 µsdauer wird nach dem 100. analogRead() gelesen
Takt-Quantisierung+0…4 µsmicros() zählt in 4-µs-Schritten

Die Abweichung ist also erklärbar und konstant, rund +0,6 %. Würde die Ist-Dauer dagegen stark anwachsen (etwa 50 ms statt 20 ms), dann käme der Prozessor dem Takt nicht nach: Die while-Schleife hätte nichts mehr zu warten, weil analogRead() allein schon länger dauert als dt. Die Zeitachse in der CSV-Datei wäre dann erfunden — sie steht ja als i · dt darin, egal wie lange es wirklich gedauert hat. Alle τ-Werte kämen zu klein heraus.

Und jetzt der Nachweis, warum man das nicht sehen kann:

Annahme: alle Zeiten sind um den Faktor k falsch, t' = k · t ln u = ln U_0 − t/tau | t = t'/k einsetzen ln u = ln U_0 − t'/(k·tau) → wieder eine GERADE, nur mit der Steigung −1/(k·tau)
Die unangenehme Folgerung: Ein Zeitbasisfehler ist ein reiner Streckungsfaktor. Er krümmt nichts, er streut nichts, er verschlechtert das Bestimmtheitsmaß nicht um ein Tausendstel. Die Gerade aus Aufgabe 7 bleibt perfekt gerade — nur dass das abgelesene τ um genau diesen Faktor k daneben liegt und damit auch C.
Also: Ein schönes Diagramm beweist nicht, dass die Messung stimmt. Es beweist nur, dass das Modell (Exponentialfunktion) passt. Ob die Achsen richtig skaliert sind, kann die Linearisierung grundsätzlich nicht verraten — das kann nur ein Vergleich mit einer unabhängigen Quelle: hier die Soll/Ist-Kontrolle des Geräts, in Aufgabe 13 die Messung mit einem völlig anderen Widerstand.
Das ist der Grund, warum der Selbsttest in der Kopfzeile steht und nicht im Handbuch. Jede Messung bringt ihre eigene Plausibilitätsprüfung mit.

Aufgabe 10 — Erst messen, dann senden

(a) Die CSV-Zeile.

eine Zeile = 10 Zeichen · 10 Bit = 100 Bit bei 115200 Baud: 100 / 115200 = 0,87 ms = 4,3 Messtakte (200 µs) bei 9600 Baud: 100 / 9600 = 10,4 ms = 52 Messtakte Speicherbedarf: 100 Werte · 2 Byte = 200 Byte von 2048 Byte = 9,8 %
Senden ist 4-mal langsamer als Messen. Würde das Gerät jede Zeile sofort ausgeben, wären nur noch alle 0,87 ms Messwerte möglich — die Zeitachse wäre nicht nur grob, sondern auch unregelmäßig, weil die Sendedauer von der Anzahl der Ziffern abhängt (1017 ist länger als 14). Deshalb: messen in den RAM, danach senden. Genau so arbeitet jedes echte Messgerät (auch das CASSY), und 200 Byte sind der Preis dafür.

(b) Die Balkenzeile — und die Überraschung.

volle Balkenzeile: 4 Ziffern + " |" + 51 Balken = 57 Zeichen 57 · 10 Bit = 570 Bit / 115200 Baud = 4,95 ms Vergleich: tau = 4,66 ms ⇒ eine Zeile dauert laenger als 1 tau !
Das Ausgeben einer Anzeigezeile kostet mehr Zeit als die ganze Kurve an Charakter hat. Würde der Balkenmodus live drucken, wäre die Entladung nach drei Zeilen vorbei — man sähe 1018, dann etwa 360, dann 130, dann Nullen. Kein Verlauf, nur Trümmer. Die Anzeige würde die Kurve, die sie zeigen soll, selbst zerstören.
Deshalb muss auch der Balkenmodus zuerst speichern, obwohl es dort überhaupt nicht auf Genauigkeit ankommt. Der Grund ist nicht Präzision, sondern Vollständigkeit: Man kann einen Vorgang nicht gleichzeitig beobachten und berichten, wenn das Berichten länger dauert als der Vorgang. Messen und Darstellen sind zwei getrennte Arbeitsschritte — das ist die eigentliche Lehre dieses Arbeitsblattes über Messgeräte.
Nebenbei: Bei 9600 Baud bräuchte dieselbe Zeile 59 ms — mehr als 12τ. Dann wäre die Kurve schon vollständig abgelaufen, bevor die erste Zeile fertig gedruckt ist.

Aufgabe 11 — Zwei harte Grenzen

(a) Nach oben: die Abtastgrenze.

DT = 200 µs > Wandlungsdauer 112 µs → zulässig Maximal möglich: 1 τ / 112 µs = 4,7 ms / 112 µs = 42 Punkte pro τ Mindestens 40 Punkte auf 4τ: 4τ ≥ 40 · 112 µs = 4,48 ms ⇒ τ ≥ 1,12 ms C ≥ 1,12 ms / 47 kΩ = 24 nF
10 nF wäre nicht mehr messbar: τ = 0,47 ms, die ganze Entladung (4τ = 1,9 ms) passt in nur 17 Wandlungen. Zu wenige Punkte für eine Ausgleichsgerade. Jedes Messgerät hat eine untere Grenze — unsere liegt bei etwa 24 nF, und wir können sie berechnen, statt sie auszuprobieren. (Abhilfe wäre nicht ein schnellerer Takt, sondern ein größerer Widerstand: 470 kΩ macht aus 10 nF wieder ein messbares τ = 4,7 ms.)

(b) Nach unten: wo das Gerät aufhört zu messen.

Die lange Messreihe über 59,8 ms (≈ 12,8 τ) zeigt es direkt: Ab t = 30,0 ms liefert der Wandler nur noch Null — 149 der 300 Punkte sind leer, nur 151 tragen überhaupt Information (ein einzelner Nachzügler bei 30,2 ms zeigt noch einmal die 1: an der Grenze zittert der Wandler zwischen 0 und 1). Das ist 6,4 τ, und es ist genau dasselbe Kriterium wie beim Ladevorgang aus Aufgabe 2, nur rückwärts gelesen:

blind, sobald u < 1 Stufe: 1018 · e^(−t/τ) < 1 t > τ · ln 1018 = 6,93 τ = 32,3 ms gemessen: ab 30,0 ms = 6,43 τ

Dieselbe Zahl 6,93, die in Aufgabe 2 die Ladezeit festgelegt hat, begrenzt auch das Messfenster. Der Dynamikbereich eines 10-Bit-Wandlers ist nun einmal 1024:1 — und in einem Exponentialvorgang sind das rund sieben Zeitkonstanten, mehr nicht. Wer länger misst, misst nichts.

Und hier lügt der ADC nicht zufällig, sondern systematisch: Ein Wandler schneidet ab, er rundet nicht — er liefert im Mittel eine halbe Stufe zu wenig. Oben ist das belanglos (bei adc 1000 sind 0,5 Stufen 0,05 %), unten ist es verheerend: bei adc 2 fehlen 25 %. In ln u zieht dieser Fehler die Punkte am Ende systematisch nach unten, die Gerade wird zu steil, und τ kommt zu klein heraus. Die Zahlen aus der 300-Punkte-Reihe:
verwendete PunktenτCR²

Der Schwanz-Fit liegt 21 % daneben — weit außerhalb der 5 % Bauteiltoleranz. Man würde den Kondensator fälschlich für Ausschuss erklären. Die Probe aufs Exempel: Rechnet man die halbe Stufe heraus und fittet ln(adc + 0,5), springt der Schwanz-Fit von 3,70 ms auf 4,25 ms — während sich der gute Bereich praktisch nicht rührt (4,670 → 4,671 ms). Genau so unterscheidet man einen systematischen von einem zufälligen Fehler: Eine Korrektur, die den Verdacht trifft, verändert nur die verdächtigen Daten.

Aufgabe 12 — Fehlerbilanz

(a) Die Spannungskalibrierung ist egal.

u = k · adc mit k = U_ref / 1023 ln u = ln(k · adc) = ln(adc) + ln k ln k ist eine KONSTANTE → verschiebt die Gerade nur nach oben/unten, die STEIGUNG bleibt unverändert
Überraschende Folgerung: Für die Bestimmung von C braucht man die Referenzspannung überhaupt nicht zu kennen. Man kann die rohen adc-Werte logarithmieren und erhält dasselbe τ. Beim Füllstandsgeber aus AB 7 war es genau umgekehrt: Dort steckte die gesuchte Größe im Absolutwert, und ohne Kalibrierung war jede Zahl wertlos. Was ein Gerät kalibriert haben muss, hängt nicht am Gerät, sondern an der Frage.

Auflösung ist nicht Genauigkeit — dieselbe Einsicht wie in AB 4, nur für die Zeitachse: Der Arduino zeigt die Zeit in 4-µs-Schritten an (Auflösung 0,02 %), aber sein Taktgeber ist ein Keramikresonator mit ±0,5 % Toleranz (kein Quarz — der sitzt auf dem Board nur beim USB-Chip). Die Anzeige ist also 25-mal feiner als der Wert stimmt. Nebenbei erklärt das, warum manche Uno-Nachbauten bei 115200 Baud nur Buchstabensalat liefern und 57600 brauchen.

(c) Ist die Abweichung echt?

Die Gesamtunsicherheit des Messgeräts liegt bei etwa 1 %, die Bauteiltoleranz des Kondensators bei 5 %. Das Gerät ist also fünfmal genauer als der Prüfling. Damit ist die gemessene Abweichung keine Messunsicherheit, sondern eine Eigenschaft dieses Kondensators — die Messung ist gut genug, um Exemplare voneinander zu unterscheiden. Das ist die Antwort auf die Frage, ob der Eigenbau etwas taugt: Für diese Aufgabe ja.
Drei unabhängige Messreihen am selben Aufbau (09.10.2026): 100 Punkte über 19,8 ms, dann zweimal 300 Punkte über 59,8 ms. Fit jeweils über adc ≥ 100:

Und jetzt die eigentliche Pointe: Die Wiederholungen streuen um ±0,05 nF. Die Unsicherheit der Widerstandsmessung mit dem Multimeter beträgt aber rund 1 %, also ±1,0 nF — zwanzigmal mehr. Das Ergebnis lautet deshalb nicht „C = 100,12 ± 0,05 nF“, sondern C = 100,1 ± 1,0 nF. Wer nur wiederholt misst, erfährt nur, wie präzise sein Gerät ist — nicht, wie richtig. Drei gleiche Werte können auch drei gleich falsche Werte sein; ein systematischer Fehler wiederholt sich ja brav mit. Die Streuung zu verkleinern bringt hier gar nichts mehr — wer genauer werden will, muss den Widerstand besser messen. Das ist Fehlerrechnung: nicht alles addieren, sondern herausfinden, welcher Posten das Ergebnis bestimmt.

Der punktweise Vergleich der beiden langen Reihen zeigt außerdem, woher die Streuung kommt: Die Einzelwerte unterscheiden sich um höchstens eine Stufe (Mittelwert der Differenz −0,05 Stufen, kein Trend über die Zeit). Das Rauschen des Wandlers ist also tatsächlich zufällig — und genau deshalb mittelt es sich im Fit über 55 Punkte fast vollständig heraus. Dass beide langen Reihen ab exakt t = 30,0 ms blind werden (149 bzw. 150 leere Punkte — der Unterschied ist genau dieses eine Zittern an der letzten Stufe), ist ebenfalls reproduzierbar: Es ist keine Zufälligkeit, sondern die Grenze des Wandlers.

Aufgabe 13 (Zusatz) — Probe mit 470 kΩ

τ = 470 kΩ · 100 nF = 47 ms (Faktor 10 langsamer) Messdauer 4τ = 188 ms → DT = 188 ms / 99 = 1,9 ms → DT_MESSEN = 2000 µs (zufaellig derselbe Wert wie DT_SEHEN) Ladezeit-Probe: 500 ms / 47 ms = 10,6 τ > 7τ → reicht noch Ergebnis: τ = 46,9 ms → C = 46,9 ms / 471 kΩ = 99,6 nF
Warum das eine starke Bestätigung ist: Die zweite Kurve sieht völlig anders aus — zehnmal langsamer, anderer Widerstand, anderer Takt — und liefert trotzdem dieselbe Kapazität. Ein systematischer Fehler des Geräts (falsche Zeitbasis, zu langsame Wandlung) müsste sich bei zehnfach anderer Zeitskala anders auswirken. Dass er das nicht tut, ist der Beweis, dass gemessen wird, was gemessen werden soll. Zwei Messungen mit verschiedenen Bedingungen sind mehr wert als zehn Wiederholungen derselben.
Ausblick — wo das Gerät sichtbar lügt: Mit R = 4,7 MΩ (τ = 470 ms, dann LADEZEIT = 3500 ms nötig) kommt der Eingangswiderstand des Wandlers ins Spiel: Die Kurve startet nur bei 4,76 V statt 4,985 V (95,5 %), und τ fällt 4,5 % zu klein aus. Aus dem Spannungsteiler lässt sich der Eingangswiderstand bestimmen: R_e = R · U_C/(U₀ − U_C) = 4,7 MΩ · 4,76/0,225 ≈ 99 MΩ. Wichtig: Dieser Effekt hängt nur an R — eine größere Kapazität macht die Kurve langsamer, aber den Fehler nicht sichtbar.
